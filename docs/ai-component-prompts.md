# AI 组件任务提示词

这份文档给人读，用来复制任务提示。`AGENTS.md` 才是给 AI 执行的仓库规则；本文件只提供更省上下文的发任务模板。

## 上下文包

每次尽量提供：

1. `AGENTS.md`
2. 下面的通用前置提示词
3. 一个任务提示词：优化既有组件，或创建新组件
4. 目标组件源码，或新组件需求
5. 仓库内调用点
6. 影响设计的相关文件：类型定义、主题 token、尺寸工具、动画工具、Provider / Host / Hook、导出入口、相邻组件

缺少关键上下文时，让 AI 先列出需要补充的文件，不要直接猜。

## 通用前置提示词

每次先复制这一段：

```text
请严格按 AGENTS.md 工作。

不要把任务理解成局部补丁。请先基于公共 API、状态模型、导出入口、调用点、Provider / Host / Hook、动画链路和相邻组件判断完整设计。

不要把我贴出的单个文件当作重构边界。缺少会影响最优设计的上下文时，先列出需要补充的文件，不要直接猜。

性能、丝滑、稳定可靠并列第一。规则是设计边界，不是最终答案；如果发现规则冲突或会损害整体设计，请先指出并给出更合理方案。

完成后必须自检：重新阅读 diff 和调用点，主动找 API 反直觉、状态竞争、边界条件、平台差异、性能回退、视觉廉价感和动画掉帧风险；发现问题继续改到位。
```

## 优化既有组件

接在通用前置提示词后面复制：

```text
任务：重构优化这个既有公共组件。

要求：
- 默认允许破坏性重构 API。现有 props、事件命名、状态模型、默认行为、配置形态如果不符合开发者直觉，请直接重新设计。
- 先判断当前问题分别属于 API、状态模型、架构边界、性能路径、动画/过渡、稳定性还是视觉交互。
- 动画、过渡、手势、高频渲染必须按关键帧路径设计，避免 JS 抖动、布局抖动、桥接开销和不必要重渲染。
- UI 尺寸新增或修改时，像素尺寸大于 0 的值必须通过 wp(...) 计算。
- 同步迁移仓库内调用点、导出入口和最少必要文档。

请先给出设计判断和最终方向，再实现改动。目标是把这个组件重构到长期可维护、API 直觉、性能路径干净、动画全程稳定的状态。
```

## 创建新组件

接在通用前置提示词后面复制：

```text
任务：设计并实现一个新的公共组件。

要求：
- 先判断这个能力是否应该进入 packages/ui；如果带业务语义、业务状态、请求、埋点或业务常量，不应放进公共组件。
- 先设计公共 API、状态模型、事件命名、默认行为、受控/非受控边界、导出方式和调用方式，再写代码。
- API 必须符合开发者直觉。同类概念优先使用 value/defaultValue、checked/defaultChecked、open/defaultOpen、onChange、disabled、loading、variant、tone、size 或 sizePreset。
- 从一开始设计干净的渲染路径、动画路径和平台差异处理。
- 动画、过渡、手势、高频渲染必须按设备刷新率稳定输出设计，不默认按 60fps 思考。
- UI 尺寸新增或修改时，像素尺寸大于 0 的值必须通过 wp(...) 计算。
- 公共入口集中在 packages/ui/src/index.ts，只更新真正影响理解的最少文档。

请先给出组件设计方案：组件职责、不应该承担的职责、props、状态模型、事件、默认行为、性能/动画策略、平台差异处理。确认设计自洽后再实现。目标是把它当成组件库的长期公共资产，而不是只满足眼前 demo。
```

## 让 AI 先补上下文

如果 AI 在上下文不足时直接开始改，复制这一句：

```text
先停一下。不要在上下文不足时猜实现。请明确列出为了做出最优公共组件设计，还需要哪些源码、调用点、Provider / Host / Hook、主题 token、尺寸工具、动画工具或导出入口。
```
